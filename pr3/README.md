# Практическая работа №3

Панель управления учебным сервисом на Bootstrap 5.3.8 и обычном JavaScript. На странице есть четыре карточки показателей, таблица операций, поиск, форма добавления записи и уведомления.

Работа находится в папке `pr3` общего репозитория практических работ.

## Запуск

Нужны Python 3, современный браузер и интернет для загрузки Bootstrap с CDN. Установка npm-пакетов и сборка не требуются.

```bash
git clone https://github.com/BKS-19/Technology-software-developers.git
cd Technology-software-developers/pr3
python3 -m http.server 8000
```

Откройте [http://localhost:8000](http://localhost:8000). Для остановки сервера нажмите Ctrl+C.

Если репозиторий уже скачан, перейдите в его папку `pr3` и выполните только команду запуска сервера. Страницу нужно открывать через HTTP: при открытии `index.html` напрямую с диска браузер может блокировать чтение JSON через `fetch`.

## Использование dataset

Папка `data` содержит копию исходного `dataset` из архива `03_Практическая_работа.zip`. Содержимое JSON и SVG сохранено без изменений.

`app.js` загружает оба JSON через `fetch` и проверяет их структуру. Из массива `metrics` файла `dashboard.json` создаются карточки «Пользователи», «Заявки», «Ошибки» и «Готовность» со значениями 128, 43, 3 и 92%. Из массива `rows` выводятся восемь операций. ID используется как идентификатор записи.

В исходных операциях нет email, поэтому в колонке ответственного отображается тире. При добавлении новой операции email берётся из формы.

Файл `notifications.json` используется для списка уведомлений и содержимого toast. Успешное сохранение показывает «Изменения сохранены», неверно заполненная форма — «Проверьте обязательные поля». Любое уведомление также можно открыть кнопкой в списке.

`avatar.svg` отображается в navbar, `chart.svg` — в блоке активности. Диаграмма является иллюстрацией из задания и не рассчитывается по операциям.

Новые операции хранятся в памяти страницы. После обновления снова загружаются исходные восемь записей. Верхние показатели остаются исходной сводкой из JSON; счётчик над таблицей показывает фактическое количество видимых операций.

## Компоненты Bootstrap

- Navbar и Collapse — навигация с раскрывающимся меню на мобильном экране.
- Container, Row, Col и utility-классы — адаптивная сетка, интервалы и выравнивание.
- Card — карточки показателей, таблицы и информационных блоков.
- Table и Table Responsive — таблица с прокруткой внутри своего контейнера на узком экране.
- Form Control, Form Select и Feedback — поля и состояния проверки формы.
- Modal — окно создания операции.
- Offcanvas — боковая справка и переключатель уведомлений.
- Toast — результат сохранения и предупреждение формы.
- Alert, Badge, List Group, Button — ошибки загрузки, статусы, список уведомлений и кнопки.

Подключены Bootstrap CSS и `bootstrap.bundle.min.js` одной версии. Bundle включает Popper. У CDN-файлов указаны `integrity` и `crossorigin`.

## Bootstrap JavaScript и собственный код

Bootstrap JavaScript открывает и закрывает Collapse, Modal, Offcanvas и Toast, управляет анимациями, фокусом, подложками и клавишей Escape. Navbar, Modal и Offcanvas открываются через `data-bs-toggle` и `data-bs-target`.

Собственный `js/app.js` читает JSON, создаёт элементы интерфейса, проверяет форму, добавляет операции, ищет записи, фильтрует их по статусу и обновляет счётчик. В нём есть отдельные обработчики отправки и ввода формы, поиска, сброса фильтров, переключателя уведомлений, событий модального окна и повторной загрузки данных.

Toast создаётся программно через `bootstrap.Toast.getOrCreateInstance(...).show()`. После сохранения Modal закрывается через `bootstrap.Modal.getOrCreateInstance(...).hide()`.

Название операции проверяется после удаления пробелов по краям: допустимо от 3 до 80 символов. Email обязателен и проверяется через `checkValidity()` поля `type="email"`. При ошибке JavaScript добавляет `is-invalid` и `aria-invalid="true"`, при успехе — `is-valid`. Под полями есть текст ошибки. Названия и email добавляются в таблицу через `textContent`.

Собственный CSS используется только для переноса длинного текста, отступа при переходе к разделам, минимальной ширины таблицы и атрибута `hidden`. Базовые стили компонентов Bootstrap не переписываются.

## Проверка

1. Откройте страницу: должны загрузиться четыре показателя, восемь операций и два уведомления. В Console и Network не должно быть ошибок.
2. На ширине 375px откройте меню navbar и перейдите к операциям. Меню должно закрыться, горизонтальной прокрутки всей страницы быть не должно. Таблица прокручивается внутри собственного контейнера.
3. Нажмите «Добавить запись» и попробуйте сохранить пустую форму. Название и email должны получить `is-invalid`, появятся подсказки и предупреждение из `notifications.json`.
4. Введите название из одних пробелов и неверный email: форма не должна сохраняться. Затем введите нормальное название и `student@example.com`: поля должны получить `is-valid`.
5. Сохраните операцию: окно закроется, в начале таблицы появится запись с ID 9, счётчик станет «Показано: 9 из 9», toast покажет «Изменения сохранены».
6. Введите в поиск `Операция 1`: останется одна исходная операция. Выберите статус «Готово»: появится сообщение о пустом результате. Сброс вернёт все строки.
7. Откройте «О панели и настройки» и выключите уведомления. Подпись сменится на «Выключены», сохранение продолжит работать без toast. Включение вернёт уведомления.
8. Закройте заполненную форму кнопкой «Отмена» и откройте её снова: значения и ошибки должны сброситься, новая запись не должна добавиться.
9. Повторите работу navbar, Modal, Offcanvas и Toast на ширине 1440px.
10. Для проверки ошибки загрузки заблокируйте запрос `data/dashboard.json` в DevTools и обновите страницу. Должно появиться сообщение об ошибке, а добавление записи будет недоступно. Снимите блокировку и нажмите «Повторить загрузку».
11. Обновите страницу: новые записи и настройки сбросятся, снова отобразятся исходные данные.

Если массив операций или уведомлений пустой, показывается соответствующее сообщение. Ошибка запроса, неверный JSON и некорректная структура данных обрабатываются в `loadData()`.

На ширинах 375 и 1440px в Chromium проверены navbar, Modal, Toast, Offcanvas, проверка полей, сохранение, отмена, поиск, фильтр статуса и переключатель уведомлений. Горизонтальной прокрутки страницы, повторяющихся ID, ошибок JavaScript и загрузки ресурсов в обычном сценарии не обнаружено. На мобильной ширине таблица прокручивается внутри responsive-контейнера.

Отдельно проверены ошибка HTTP с повторной загрузкой, повреждённый JSON, неверная структура данных и пустые массивы операций и уведомлений. Изменение показателя в ответе JSON отображается в соответствующей карточке.

## Этапы работы

Сначала добавлены структура панели, исходные данные и вывод карточек с responsive-таблицей. Затем реализованы Modal с формой, валидация и Toast. Следующим этапом добавлены поиск, счётчик, Offcanvas и переключатель уведомлений. В завершение подготовлена инструкция запуска и проверена работа компонентов.
